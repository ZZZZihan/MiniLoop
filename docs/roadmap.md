# MiniLoop 实施清单

**所有任务均未开始、未验收。** 本文件定义后续开发顺序，不是完成记录。每项完成时附对应提交、运行命令与证据路径，再勾选。

## P0：能运行、能解释的最小内核

### P0-01 最小真实工具调用循环（首个任务）

- [ ] 选择一个真实模型及单个适配器，记录配置和依赖版本。
- [ ] 建立只读演示文件与 `read_file` 工具，限制到演示工作区。
- [ ] 实现任务 → 模型调用 → 工具执行 → 结果回填 → 模型终止。
- [ ] 保存真实请求响应、调用 ID、实际文件结果与退出原因，不包含密钥。

**验收：**模型确实请求工具，程序确实读取文件，下一轮模型确实收到关联结果。凭模型直接回答、写死流程或确定性替身输出，均不能标记本项通过。此时只需最小记录，不要求完整 JSONL 回放功能。

### P0-02 工具协议与错误处理

- [ ] 工具通过注册接入；校验工具名、必需字段、类型及调用 ID。
- [ ] 明确未知工具、错误参数、工具异常和协议错误的处理方式。
- [ ] 能正确处理同一轮多个调用，首版顺序执行并逐个关联结果。
- [ ] 引入确定性模型替身，验证协议行为；替身与真实模型入口明确区分。

**验收：**参数错误在副作用前被拦截；调用关联不依赖模型返回顺序的猜测；没有返回错误后无限循环的路径。至少保留一条失败轨迹和修正说明。

### P0-03 预算、超时与退出

- [ ] 实现模型调用上限、工具调用上限、总耗时预算与单次操作超时。
- [ ] 区分正常结束、预算耗尽、模型错误、协议错误、取消与运行时错误。
- [ ] 所有重试计入预算；超限后不再启动新的工具或模型请求。
- [ ] 使用确定性替身覆盖边界，真实调用仅验证适配器实际行为。

**验收：**无限请求工具的替身在上限处停止；超时有可解释结果；正常结束不自动标记任务成功。记录计数规则与已知取消限制。

### P0-04 一个真实代码修复任务

- [ ] 制作有稳定故障、参考修复和固定测试的小型 Python 案例。
- [ ] 实现提出差异、确认和应用差异，只修改演示副本的允许源码。
- [ ] `run_tests` 使用固定入口，模型不能修改评分测试或执行任意命令。
- [ ] 真实模型完成读取、提出修改、确认后应用及测试验证；保留失败尝试。

**验收：**参考修复先由人工验证可行；真实模型的“修好”说法不能代替测试结果；目标文件和约束保持完整。无法完成时记录失败，不调整评分规则掩盖结果。

## P1：可检查的轨迹与可信交付

### P1-01 JSONL 轨迹与只读回放

- [ ] 固定事件字段和版本，覆盖模型、工具、错误、预算及终态。
- [ ] 回放只读文件，不执行工具或请求模型。
- [ ] 显示调用 ID 关联，并明确提示损坏、截断及缺失事件。

**验收：**回放前后演示工作区内容一致；用能计数的替身确认工具执行次数和模型调用次数均为零。不要把轨迹回放称为中断恢复。

### P1-02 分开记录协议验证与真实任务评测

- [ ] 覆盖正常结束、错误参数、未知工具、工具超时、模型错误、预算耗尽、拒绝修改、调用关联错误等协议情形。
- [ ] 先准备 5–8 个独立修复案例作为规划起点，不通过重复改文件名凑数量。
- [ ] 固定任务分组、模型、提示词、预算和验证器，保留首次完整结果。
- [ ] 分别报告协议结果与真实任务完成数、耗时和失败原因。

**验收：**能从汇总追溯逐例轨迹和评分；未执行项明确标为未执行；不借用上游成绩。详细规则见 [评测协议](evaluation.md)。

### P1-03 可复现交付与本人讲解

- [ ] 补充实际启动命令、配置加载说明、演示案例和常见错误。
- [ ] 在干净环境重新安装并按 README 运行一次，记录实际结果。
- [ ] 更新参考版本、复用代码归属和本人新增实现。
- [ ] 能解释一条真实失败轨迹，并在不改主循环的情况下增加一个工具。

**验收：**文档、运行行为和简历描述一致。实现范围外的能力继续留在未实现列表，不把完成一段教学示例写成完整生产级平台。
