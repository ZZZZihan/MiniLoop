# MiniLoop

一个用于理解和验证模型工具调用机制的 Python 项目。目标是在小型演示仓库中完成读取文件、提出修改、执行受限操作和检查结果，并保留可检查的执行轨迹。

## 当前状态

**当前仅有架构、实施计划和可安装的空包，运行时功能全部未实现。** 项目尚未调用真实模型，未提供 CLI、工具、评测数据或测试结果。文档中的功能和验收条件均是后续工作目标。

## 项目要证明什么

- 能解释模型如何请求工具、程序如何执行工具，以及结果如何回填到下一轮模型输入。
- 能处理无效参数、未知工具、超时与预算耗尽，并留下清楚的退出信息。
- 能在冻结的小型代码修复任务中区分协议正确性与模型任务完成能力。
- 能根据一条失败轨迹定位问题，并说明本人实现与开源参考的关系。

首版仅支持一个模型适配器、一个串行执行循环和一个本地演示工作区。暂不实现 Web 平台、多智能体、插件市场、长期记忆、上下文自动压缩或中断任务恢复。项目不替代业务应用中的 LangGraph 等框架实践。

## 首个任务：最小真实工具调用循环

从只读任务开始，不先搭建完整框架：

1. 创建一个内容固定的演示文件，并定义只读 `read_file` 工具。
2. 向一个真实模型提供任务及工具定义，由模型返回工具调用和参数。
3. 程序解析并执行调用，将结果关联到原调用 ID，再发给模型。
4. 模型根据工具返回给出最终答复，程序退出。
5. 保存本次使用的模型标识、输入、原始输出、实际工具结果及退出原因。

验收必须观察到真实模型请求、实际文件读取和工具结果回填。确定性替身可用于排错，但替身演示不能记为真实模型通过。具体步骤见 [实施清单](docs/roadmap.md)。

## 当前能安装什么

需要 Python 3.12 或更新版本。在独立虚拟环境中执行：

```bash
python -m pip install -e .
python -c "import miniloop; print(miniloop.__version__)"
```

以上只安装并导入空包，不会运行 Agent、读取 `.env` 或调用模型。构建使用 setuptools；当前没有运行时依赖，依赖将在具体实现需要时添加。`.env.example` 仅列出未来配置项，所有值为空，尚无配置加载器。
